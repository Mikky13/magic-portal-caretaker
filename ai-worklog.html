1. Обзор проекта

Приложение представляет собой симуляцию командного терминала для мониторинга и сдерживания межпространственных разломов (порталов). Это полностью клиентское приложение — без серверной части, без API, без базы данных — работающее исключительно в браузере на HTML, CSS и JavaScript.

Пользователь выступает в роли «Хранителя Порталов», который отслеживает активные разломы, оценивает уровень риска, выполняет действия по сдерживанию и реагирует на автоматическое появление новых порталов.

3. Архитектурные решения

РешениеОбоснование
Чисто клиентская архитектура (без сервера)Упрощённое развёртывание — достаточно открыть index.html в браузере. Нет зависимости от Python/Flask, нет проблем с CORS, нет конфигурации сервера.
Единственный файл app.jsВся логика в одном файле для простоты. Не требуется сборщик модулей. Легко поддерживать для проекта данного масштаба.
Состояние только в памятиНет localStorage или персистентности — приложение является симуляцией. Данные сбрасываются при обновлении страницы, что является ожидаемым поведением для терминала мониторинга.
Делегирование событий на #portals-table и #modal-overlayВместо привязки обработчиков к каждой кнопке (которые ломаются при перерендере) используется делегирование событий на родительские контейнеры. Это более производительно и надёжно.
Авто-обнаружение через setTimeout + setIntervalПервое обнаружение задерживается на 5 секунд (чтобы пользователь увидел пустой терминал), затем повторяется каждые 15 секунд. Ограничение до 8 активных порталов предотвращает проблемы с производительностью.
Формула риска: (Энергия × 1.5) + (100 − Стабильность) + (300 ÷ max(Схлопывание, 1))Простая, прозрачная и объяснимая. Энергия имеет наибольший вес, нестабильность оказывает значительное влияние, а временнóе давление (малое время до схлопывания) создаёт срочность. Три порога (60/100/150) обеспечивают чёткие категории риска.
CSS без CSS-переменныхИспользованы прямые значения для простоты и единообразия. Градиенты и тени используются для визуальной глубины без сложности.
Web Audio API для звукаВстроенный браузерный API — никаких внешних библиотек. Простые звуковые эффекты на основе осциллятора для каждого типа действия.
Обработка модального окна через единый обработчик оверлеяКонсолидирует обработку кнопки закрытия, клика по оверлею и кнопок обновления. Избегает конфликтов между вложенными обработчиками событий.

5. Сводка функциональности

  • Таблица порталов: Отображает все активные (незакрытые) порталы с названием, миром назначения, полосой энергии, полосой стабильности, таймером схлопывания, количеством существ, статусом, бейджем риска, оценкой риска и кнопками действий
  • Карточка портала: Клик по названию открывает подробную информацию — разбор риска с формулой, рекомендуемые действия, раздел обслуживания, полная история изменений
  • Движок риска: Расчёт в реальном времени с цветными бейджами (Низкий / Средний / Высокий / Критический)
  • Действия: Стабилизация, Закрытие (с подтверждением если есть существа), Эвакуация, Отправка наблюдателя, Пометка «Под вопросом» — каждое с логическими ограничениями
  • Обслуживание портала: В модальном окне — укрепление стабильности, снижение энергии, добавление времени
  • Авто-обнаружение: Новые порталы появляются каждые 15 секунд (первый через 5 сек), максимум 8 активных
  • Симуляция тика: Каждые 2 секунды порталы деградируют, могут провалиться и схлопнуться
  • Журнал событий: Хронологический журнал всех событий и действий
  • Дашборд: Живая статистика — открытые порталы, критические угрозы, запечатанные, требующие внимания
  • Звуковые эффекты: Синтезированные звуки Web Audio API для каждого действия
  • Уведомления toast: Анимированные уведомления о событиях и результатах действий
  • Диалоги подтверждения: Для разрушительных действий (принудительное закрытие, сброс системы)
  • Адаптивный дизайн: Работает на десктопе, планшете и мобильном устройстве
